# Второй проход по производительности

Проверка выполнена 11 октября 2026 года от `706bebe`. Меняется загрузка модулей и обработка данных; композиция страниц и глобальные стили сохраняются.

## Изменения

- `main.tsx` выбирает App либо CaptureWindow и загружает только выбранный модуль. Скрытое окно быстрого захвата не импортирует полный интерфейс приложения; его слушатели монтируются при загрузке собственного небольшого модуля.
- `App.tsx` загружает редактор при открытии заметки: Editor2026 для обычных заметок, MarkdownSourceEditor для импортированного исходника. Границы загрузки имеют локализованный статус, читаемый цвет из темы и существующую обработку ошибок. Порядок базовых CSS и index.css сохранён.
- Полнотекстовый слой разделяет ожидающее чтение одного id/updatedAt между прогревом, поиском и подсчётом слов. Старое завершение не заменяет новую версию тела; старый запрос списка не вычищает кэш более нового списка. Отклонённые запросы освобождаются для повтора.
- Модель Обзора переиспользует нормализованные теги и календарную дату неизменённых метаданных через WeakMap. Проверяются также исходные значения тегов. Кэш не содержит тела Markdown и освобождается вместе с метаданными. Агрегация и сравнение заметок остаются линейными.

После объединения с `codex/all-notes-redesign` автоматический прогрев полнотекстового поиска при запуске убран. Старт загружает метаданные; полные тела читаются по запросу поиска, графа, статистики или конкретной заметки. Отсутствующая при временной ошибке заметка не кэшируется как пустая навсегда. Метаданные и встроенные шаблоны по-прежнему используют локальный IO при старте.

## Измерения

Таблица ниже сохраняет измерения первоначального прохода ветки `codex/runtime-performance` до объединения. Дополнительный проход `codex/all-notes-redesign` проверил фактический граф загружаемых модулей: библиотека использовала примерно 0,99 МБ JS вместо 2,55 МБ, быстрый захват — 0,25 МБ. Два нативных замера на копии библиотеки показали 3,05–3,64 CPU-секунды до и 1,43–2,67 после за первые 12 секунд. Это затраты CPU, не время первого кадра. Сумма RSS в той же точке составляла 510–529 МиБ до и 235–326 после; она включает общие страницы процессов и не равна уникальной физической памяти. Эти дополнительные замеры выполнены при заблокированном Mac.

Размер JS относится только к входному файлу: общий код приложения распределён по дополнительным модулям и остаётся доступным. Это не десятикратное уменьшение всего приложения или времени запуска.

Кэш метаданных ускоряет повторную обработку, но имеет цену первого заполнения. Отдельный перемежающийся тест на новых объектах 50 000 заметок показал медианы около 43,6 мс до и 53,8 мс после. Этот компромисс не скрывается: повторные небольшие изменения выигрывают, а первый полный проход создаёт записи кэша. На браузерной fixture после изменений начальный commit занял 48,4 мс; обновление метаданных добавило около 14 мс. Эти значения не измеряют нативный FPS или запуск приложения.

В исходной копии обычная библиотека за 20 секунд потребляла около 0,05% одного логического ядра, свёрнутая — около 0,02%. Дисковое чтение и запись по process counters за эти интервалы были нулевыми. В оптимизированной копии первоначально открытая библиотека также оставалась практически в покое. Уверенного вывода о проблеме постоянного фонового расхода в этом сценарии нет.

После первой загрузки редактора и статистики оптимизированная копия в свёрнутом состоянии за 20 секунд показала около 0,03% ядра, 0,05 package wakeups в секунду и нулевые дисковые counters. В этом состоянии код редактора уже загружен: footprint около 333 МиБ не сравнивается с 222 МиБ первоначальной библиотеки. TCP/UDP process summaries за этот интервал не содержали активных соединений; это локальный короткий сценарий, а не утверждение о сетевой активности любого содержимого заметок.

## Методика и границы

Использованы отдельные подписанные macOS app bundles с отдельным identifier и копией локальных данных. Рабочее хранилище не используется для тестовых записей. В копии проверены первоначальная библиотека, создание тестовой заметки и первая загрузка редактора, переход в Обзор и итог слов на реальных скопированных текстах. Синтетическая браузерная fixture подтверждает восемь начальных строк, нулевой подсчёт слов до явного выбора показателя и один запрос после выбора.

macOS sampler собирает cumulative process counters основного процесса, GPU/Networking и двух WebContent-процессов. Helper PID проверяется по запуску и выходу соответствующей копии; чужие процессы исключаются. CPU считается относительно одного ядра, не всей машины. Mach timebase учитывается и проверяется на CPU-времени самого sampler. Footprint — сумма process charges, включая WebKit; WindowServer и общий расход GPU/батареи сюда не входят. Дисковые counters не учитывают как физический IO каждое чтение, обслуженное файловым кэшем.

Первичный замер рабочего приложения с открытым графом совпал с изменениями окна и не используется как подтверждение расхода в простое. Сравнение батареи в ваттах, часов автономности, Obsidian и производительности на другой видеокарте не проводилось. Время вызовов инструмента управления окном не выдается за время запуска Tauri.

node --test tests/*.test.mjs
node tools/perf/overview-benchmark.mjs
npm run build
python3 tools/perf/sample_macos.py --pids APP_PID,HELPER_PID --seconds 20 --label idle --out /tmp/synapse-idle.json
