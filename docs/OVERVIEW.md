# Обзор: рабочий стол и статистика

Обзор открывается как рабочий стол: продолжить активную или последнюю изменённую заметку, создать обычную или дневную запись, найти материал через существующую командную палитру. Подробная статистика вынесена во вторую вкладку и загружается по запросу.

Это локальное расширение существующего дизайна Synapse. Сохранены Inter/system, семантические цвета приложения, настраиваемый акцент, мятные теги, плоские рабочие области и тонкие разделители. Композиция и размеры Overview описаны в [surface brief](../.impeccable/surfaces/src-components-writingdashboard-tsx.md); они не становятся глобальными правилами [DESIGN.md](../DESIGN.md). Производственных растров в Overview нет.

Общая ветка доставки объединяет завершённые реализации Обзора, «Всех заметок» и «Изображений». После интеграции PRODUCT.md, DESIGN.md и `.impeccable/design.json` включают документацию и локальное расширение All Notes. Базовые цвета и типографика сохраняются; этот проход документирует Overview без переписывания общего дизайна или документов других разделов.

## Реализация и границы нагрузки

| Файл | Ответственность |
| --- | --- |
| [WritingDashboard.tsx](../src/components/WritingDashboard.tsx) | Рабочий стол, действия, фильтры, локальный день и отложенная загрузка статистики. |
| [overviewModel.ts](../src/lib/overviewModel.ts) | Единая модель метаданных: уникальные заметки, недавние, избранное, темы, разделы и даты изменения. |
| [OverviewAnalytics.tsx](../src/components/dashboard/OverviewAnalytics.tsx) | Выбор показателя и периода, графики, связанные заметки, загрузка и восстановление после ошибки. |
| [overviewWords.ts](../src/lib/overviewWords.ts) | Общий ресурс необязательного подсчёта слов и точная проверка версии метаданных. |
| [OverviewNoteRow.tsx](../src/components/dashboard/OverviewNoteRow.tsx), [overview.css](../src/components/dashboard/overview.css) | Мемоизированная строка, локальная типографика, адаптация и фокус. |
| [overviewFormat.ts](../src/lib/overviewFormat.ts) | Русские/английские формы чисел и очистка начальных тегов только в отображаемом фрагменте. |
| [commandPaletteEvents.ts](../src/lib/commandPaletteEvents.ts) | Явный запрос открытия существующего глобального поиска. |

Рабочий стол использует только `NoteMeta`, включая готовый `preview`; он не запрашивает тела Markdown ради отображения виджетов. `WeakMap` переиспользует модель для той же ссылки на дерево. Новая ссылка вызывает новый проход по метаданным; небольшие списки выбираются без сортировки всех заметок. Темы и разделы сортируются после агрегации. Ограничено количество результатов и элементов интерфейса, а не стоимость всего прохода по базе.

В рабочем списке показываются до 8 заметок, в боковом избранном — до 5, тем — до 7, разделов — до 6. Раздел определяется первым сегментом папки, заметки без папки образуют отдельную группу. Модель устраняет повторные id, а счётчики тем учитывают нормализованный тег один раз на заметку. Лента последних изменений содержит 30 локальных календарных дней; выбор дня сочетается с фильтром недавних, избранных или заметок без тегов. Повторный клик, кнопка сброса или Escape снимает фильтр даты.

Сам Overview загружается через `lazy` в App; модуль статистики — только при переходе во вкладку. Её исходный показатель «Заметки» также работает по метаданным. Только выбор «Объём текстов» вызывает динамически загружаемый `wordCountsFor` из существующего полнотекстового слоя.

В bootstrap [App.tsx](../src/App.tsx) удалены импорт и безусловный фоновый вызов `wordCountsFor(flatNotes)`. Сохранён `warmIndex(flatNotes)`: полнотекстовый поиск по-прежнему прогревает кэш и может читать тела заметок после загрузки дерева. Прежний параллельный прогрев поиска и слов мог повторять чтения ещё холодного кэша. Поэтому «метаданные сначала» описывает модель и виджеты Overview; это не обещание отсутствия чтения Markdown во всём приложении при запуске.

Ресурс слов сравнивает каждый `id`, `createdAt` и `updatedAt`, а не длину массива или максимальную дату. Тот же набор при другом порядке, изменённом заголовке или признаке избранного переиспользует запрос. Совпадение загрузчика тоже обязательно. Ожидающие и завершённые запросы разделяются между возвращениями во вкладку; разные снимки выполняются последовательно. Ошибка освобождает запрос для повтора, а завершение старого эффекта не публикует результат в новую версию интерфейса.

Счётчики загрузки отображают многоточие. После ошибки оба итога слов становятся «—» с доступным именем «Недоступно» и действием «Повторить»; старые итоги, выбор периода и значения слов в тепловой карте не выдаются за актуальные.

## Что означают показатели

| Показатель | Определение |
| --- | --- |
| Последние изменения / график «Заметки» | Текущие файлы по последнему `updatedAt`; каждый файл учитывается один раз. Это не журнал операций: новое изменение переносит файл в другой день. |
| Объём текстов | Текущие тела заметок, сгруппированные по их `createdAt`. Редактирование старой заметки меняет значение её исходного периода; график не показывает, сколько слов написано в день редактирования. |
| Слова | Существующий `countWords`: максимальные непробельные фрагменты Markdown. Разметка может влиять на число; это технический счётчик, а не лингвистический анализ прозы. |
| Ежедневные записи и серия | Наличие файлов, распознаваемых как дневные записи по id и дате. Серия не доказывает объём написанного текста. |

При клике на столбик статистики показываются до 6 связанных заметок: по дате изменения для «Заметок» и по дате создания для «Объёма текстов». Дневная запись открывается или создаётся только по нажатию её действия; просмотр Обзора и тепловой карты сам запись не создаёт.

## Адаптация и взаимодействие

Композиция следует ширине контейнера с порогами 1000, 750 и 480 px. На узком экране рабочие области переходят в одну колонку, второстепенные метаданные строк сокращаются. Интерактивные дни и столбцы сохраняют ширину не менее 24 px с промежутками; их область прокручивается горизонтально. Лента раскрывает сегодняшний край, график — текущий период. Числовая ось графика остаётся слева на непрозрачном фоне при прокрутке столбцов.

Вкладки поддерживают стрелки, Home и End; такие же клавиши перемещают фокус между столбцами. Есть видимый `focus-visible`, доступные названия и состояния выбранных элементов. `ResizeObserver`, таймер дня и слушатели освобождаются при завершении соответствующего эффекта. Небольшое движение стрелки действия отключается при `prefers-reduced-motion`.

## Как воспроизвести проверки

Из корня проекта с установленными зависимостями:

```sh
node --test tests/overview.test.mjs
node --test tests/*.test.mjs
npm run build
npm run tauri -- build --bundles app
```

Девять [Overview-тестов](../tests/overview.test.mjs) проверяют модель без изменения источника, ограничения на 50 000 заметок, фильтры дат, календарные границы, смену id и дат, косметические изменения и порядок, последовательность запросов, повтор после ошибки и локализованный текст. До интеграции общий прогон дал 56 прошедших тестов; после объединения готовых разделов и удаления подсчёта слов из bootstrap — 71 из 71, 0 ошибок и 0 пропусков (`all-tests-integrated.log`). Финальный интеграционный лог `overview-app-build-integrated.log` подтверждает TypeScript/Vite и создание macOS app bundle. Это подтверждение сборки; установка и запуск установленного приложения проверяются отдельно.

Безопасная браузерная fixture:

```sh
npm exec vite -- --config tests/overview.vite.config.mjs
```

Открыть `http://127.0.0.1:1442/tests/fixtures/overview.html` с одним из вариантов:

| Параметры | Проверка |
| --- | --- |
| `?notes=50000` | Большая синтетическая база, ограниченные строки и отложенный подсчёт слов. |
| `?empty=1` | Пустая база и действия начала работы. |
| `?notes=9&error=1&controls=1` | Первая ошибка и успешный Retry после «Чтение доступно». |
| `?notes=9&controls=1` | Кэш при «Метаданные»; повторная ошибка после «Чтение недоступно» и «Обновить текст». Последнее действие меняет только метку версии fixture. |

Открытие/создание заметки и дневной записи подменены тестовыми обработчиками; поиск использует документы fixture. Без `vault` данные синтетические. `#overview-metrics` содержит JSON со счётчиками запросов слов, обработанных строк, React commits и суммой `Profiler.actualDuration`; переходы записываются в его `data-action` и `data-note`. Сценарий кэша: рабочий стол → «Статистика» → «Объём текстов» → «Метаданные» → перейти из Обзора и вернуться.

Для 50 000 синтетических заметок сохранённый браузерный прогон показал 8 строк в начальном списке, 0 запросов слов на рабочем столе и в статистике метаданных, 1 после явного выбора объёма текстов, всё ещё 1 после смены избранного и тёплого возврата. Начальный commit Overview занял около 38,2 мс по React Profiler. Отдельная fixture с метаданными 530 заметок показала такую же последовательность запросов. Это измерения браузерной fixture, не время запуска Tauri, FPS, нагрузка на батарею или задержка чтения диска. Счётчик `wordRequests` отражает запросы тестового загрузчика слов; fixture не запускает bootstrap App и не измеряет чтения при прогреве поиска.

## Finish и ограничения

Финальный finish verdict имеет `disposition: ship` для исправленных пунктов: иерархии шрифтов контролов, узких целей дат/столбцов, недоступных итогов при ошибке и остающейся видимой оси Y. Проверена та же матрица из пяти снимков: рабочий стол 1440×900, 1280×720 и 390×844; статистика 1440×900 и 390×844. Это проверка заявленных исправлений, а не гарантия для любых состояний приложения. Однократный detector дал рекомендации; их значения не превращены в правила глобального дизайна.

Проверки выполнялись в тёмной теме. Светлая тема не получила подтверждения поддержки или полноценной визуальной проверки. Большие существующие чанки фронтенда продолжают вызывать предупреждение Vite. Кэш слов живёт в памяти текущего процесса; изменение тела без обновления метаданных `updatedAt` не обнаруживается этим контрактом. Отдельная native проверка чтения большой базы и широкая проверка с ассистивными технологиями здесь не заявлены.

`tests/fixtures/overview-vault.json` — необязательный частный снимок и исключён через `.gitignore`. Он, снимки экрана с реальными заметками и локальные артефакты проверок не должны попадать в коммит или публикуемые материалы. Для воспроизводимой публичной проверки используются синтетические варианты выше.
