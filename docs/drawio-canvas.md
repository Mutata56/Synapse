# Холст с локальным draw.io

Холст внутри заметки использует полный браузерный редактор **draw.io 32.4.1** из закреплённого Desktop-дистрибутива. Библиотеки фигур, трафареты, страницы, слои, выравнивание, соединения, компоновки и undo/redo обслуживает draw.io. Synapse управляет открытием, файлами и сохранением схемы в заметку.

Редактор загружается при открытии доски. Его код и ресурсы лежат в `public/drawio/`; облачная авторизация, Electron-оболочка и публичные серверы хранения/экспорта заменены локальными адаптерами Synapse. Импортированные пользователем внешние изображения, шрифты или формулы могут требовать дополнительных ресурсов.

## Работа с холстом

1. Вставьте существующий блок «Холст»/«Доска» и задайте название в карточке заметки.
2. Нажмите «Открыть доску». Внутри полноэкранного диалога доступны меню, панель фигур, инспектор и страницы draw.io.
3. Верхняя панель Synapse содержит открытие файла, восстановление предыдущего холста при наличии копии, формат и действие экспорта, сохранение и закрытие. Кнопки имеют доступные названия и видимый фокус.
4. Изменения автоматически попадают в блок заметки. «Сохранить» подтверждает запись через существующий механизм сохранения заметки. Закрытие сначала фиксирует активную подпись и схему, затем дожидается сохранения заметки; ошибка оставляет холст открытым и предлагает повторить сохранение.

Фокус остаётся внутри диалога и редактора; фон приложения становится `inert`. После успешного закрытия фокус возвращается к кнопке открытия доски. При ширине до 800 px панель уменьшает отступы и скрывает вторичный статус, сохраняя доступ к действиям.

## Импорт и восстановление

Кнопка «Открыть файл схемы» принимает `.drawio`, `.xml`, а также PNG, SVG и PDF со встроенной моделью draw.io. Обычная картинка или PDF без модели не превращаются в редактируемую схему: появляется сообщение об отсутствии встроенной диаграммы. Пустые файлы, некорректные данные и файлы больше 100 МиБ отклоняются.

После выбора файла появляется подтверждение: файл **заменит текущий холст**. Действие «Заменить холст» сохраняет предыдущий документ в одном поле `importBackup`; «Отмена» сохраняет текущую схему. Восстановление меняет местами текущую схему и эту копию. Вложенная история копий не накапливается. Копия записывается вместе с блоком и остаётся доступной после сохранения, закрытия и повторного открытия заметки.

При ошибке загрузки исходный документ возвращается в редактор. HTML и JSON отсутствуют в фильтре импорта хоста: HTML служит экспортом для просмотра, а JSON возвращает формат штатного экспортного протокола draw.io.

## Перенос прежних досок

Тип блока остаётся `whiteboard`, свойства `snapshot` и `name` остаются строками. Старый JSON преобразуется при чтении в документ `{ engine: "drawio", version: 1, xml, ... }`. Документ записывается при штатном flush/save через прежний блок и механизм сохранения заметок.

Конвертер поддерживает прямоугольники, эллипсы, стрелки, перо, текст, базы данных, действия/процессы/решения и заметки/sticky. Фигуры и связи становятся редактируемыми ячейками draw.io: переносятся координаты и размеры, точки пера, подписи, привязки сторон, маршрутизация, оформление и блокировка. SQL из блока базы данных сохраняется как редактируемое свойство `query`.

Точная исходная строка JSON, включая пробелы и неизвестные поля, сохраняется в `legacySnapshot` и в корневом `UserObject` модели (`synapseLegacySnapshot`, `synapseCamera`). Отдельные фигуры сохраняют свои исходные данные в `synapseLegacyData`. Служебные поля восстановления скрыты из обычного диалога свойств и подсказок; они остаются в XML и редактируемых экспортах.

Некорректный JSON/XML, неподдерживаемый тип фигуры, отсутствующая связь или непредставимая геометрия вызывают ошибку. Карточка сообщает, что исходные данные сохранены, и блокирует открытие. Ошибочные данные не заменяются пустым холстом. Пустая исходная строка создаёт новую пустую схему.

## Форматы экспорта

| Формат | Изображение и страницы | Редактируемая модель |
| --- | --- | --- |
| `.drawio` | XML всего файла, включая все страницы | Исходный `mxfile` |
| SVG | Изображение активной страницы | XML файла в атрибуте SVG `content` |
| PNG | Растр активной страницы | XML файла в текстовом PNG-носителе |
| HTML | Просмотр всех страниц с постоянной панелью, переключением страниц, масштабом и слоями | Полный XML в `data-mxgraph`; закреплённый viewer встроен в файл |
| JSON | Результат штатного JSON-экспорта draw.io | Не является форматом импорта хоста |
| PDF | Векторные страницы; экспорт реализован для macOS | Полный XML в `Info/Subject` и вложении `.drawio`/`.xml` |

HTML собирается хостом из полного XML и `drawio/js/viewer-static.min.js`. В нём включены `toolbar: "pages zoom layers lightbox"`, `toolbar-nohide: 1`, начальная страница `0`, `nav` и `resize`. Переключатель страниц появляется для многостраничного файла. Штатный `html2` в режиме EmbedFile выдаёт перенаправление в редактор, поэтому для переносимого просмотра используется сборка хоста. Внешние пользовательские изображения, дополнительные шрифты, математика и отдельные ресурсы фигур могут потребовать ресурсов сверх встроенного viewer; наличие viewer и XML не гарантирует автономность любой импортированной схемы.

PNG зависит от поддержки браузером отрисовки SVG/`foreignObject` в canvas. Хост распознаёт точный пустой растр, который upstream возвращает при неудачной отрисовке, и предлагает SVG вместо сохранения такого PNG. Обычные допустимые изображения размером 1×1 не отклоняются только из-за размера.

PDF строится по одной SVG-странице через отдельный редактор экспорта, сохраняя активную страницу и undo/redo основного редактора. На macOS каждая страница поступает в изолированный непостоянный `WKWebView`; CSP запрещает скрипты страницы и сетевые ресурсы. PDFLib объединяет векторные страницы, приводит размеры из CSS px к PDF pt и прикрепляет полный XML. Экспорт не снимает видимую заметку или рабочее окно. На Windows, Linux и в браузерном режиме векторный PDF явно сообщает, что эта возможность доступна только в приложении для macOS.

В Tauri импорт и экспорт используют системные диалоги и файловый плагин. В браузерной проверке используются выбор файла и скачивание через Blob. Отмена диалога не записывает файл.

## Где находится реализация

| Файл | Ответственность |
| --- | --- |
| [whiteboardBlock.tsx](../src/editor2026/blocks/whiteboard/whiteboardBlock.tsx) | Схема блока, карточка, ленивое открытие, фокус и `inert`, очередь сохранения заметки |
| [DrawioCanvas.tsx](../src/editor2026/blocks/whiteboard/DrawioCanvas.tsx) | Верхняя панель, iframe, viewport, подтверждение импорта, восстановление и экспорт |
| [drawioDocument.ts](../src/editor2026/blocks/whiteboard/drawioDocument.ts) | Формат документа, проверка XML, перенос старой геометрии и точная копия оригинала |
| [drawio.css](../src/editor2026/blocks/whiteboard/drawio.css) | Локальные стили панели и состояний Synapse |
| [drawioBridge.ts](../src/lib/drawioBridge.ts) | JSON `postMessage`, handshake, request ID, таймауты и поколения сессии |
| [drawioFiles.ts](../src/lib/drawioFiles.ts) | Диалоги, декодирование файлов, встроенный XML, HTML-viewer и сборка PDF |
| [canvas_pdf.rs](../src-tauri/src/canvas_pdf.rs) | Изолированный векторный WebKit-renderer macOS и явная ошибка остальных платформ |
| [vendor-drawio.mjs](../scripts/vendor-drawio.mjs) | Воспроизводимая локальная адаптация проверенного upstream и проверка опубликованных байтов |

`configure → init → load` согласует настройки и начальную схему. Входящие события принимаются только от выбранного iframe с совпадающим origin. Запросы экспорта коррелируются по `requestId`; обычный экспорт сериализован, перезапуск или закрытие отклоняют незавершённые запросы. Активная подпись фиксируется через `resetEditor` перед получением XML.

Изменения блока имеют debounce 600 мс. Обязательный flusher фиксирует последний autosave до ожидания свежего XML из iframe и затем передаёт управление сохранению заметки. Превью запрашивается после загрузки/изменения с задержкой 1200 мс; ограничено 16 МиБ и принимается только если XML с момента запроса не изменился. Документ также хранит страницу, масштаб и прокрутку. Исходный Canvas-2D остаётся для совместимого превью старой доски; живое редактирование выполняет draw.io.

## Ресурсы и происхождение

Состояние закреплённой копии описывают [NOTICE](../public/drawio/NOTICE), [vendor-manifest.json](../public/drawio/vendor-manifest.json), [viewer-origin.json](../public/drawio/viewer-origin.json) и [embed-contract.json](../public/drawio/embed-contract.json). Manifest содержит upstream и опубликованные SHA-256 каждого копируемого файла, локальные изменения и исключения. Копия редактора содержит **2765 файлов, 59 486 476 байт** по проверке manifest; отдельно сохраняются принадлежащие хосту PDFLib-файлы. Это размер локальных ресурсов, а не размер начального JavaScript приложения и не измерение времени запуска.

Источник — draw.io Desktop 32.4.1 с SHA-256 `app.asar` `e4245dea2cc2325dab61fcd2aa578e0a4bc539559d9c96160369cdb42eb19cc0`. Дополнительный официальный HTML-viewer взят из коммита `9034053fba80a435e27d68d374bc564b83917ae9`, SHA-256 `bc7586cb62eec98018c13b78619078d3a7179cc7bfc711c566dda19527520a30`. Его оригинальные байты сохранены между маркерами внутри `js/viewer-static.min.js`; перед ними находится локальная обёртка. `js/embed-static.min.js` — авторский alias этого viewer, поскольку официальный такой путь отсутствует в закреплённом теге.

Вложенный исходный draw.io сохраняет Apache-2.0; Desktop-дистрибутив — GPL-3.0-only; шаблоны — CC BY 4.0. Трафареты, изображения, libavoid-js и остальные библиотеки сохраняют свои лицензии и уведомления, включая указанное upstream ограничение Atlassian. Полные условия и расположение файлов перечислены в NOTICE. Метаданные происхождения добавлены к растровым ресурсам без изменения потоков пикселей.

Проверить опубликованную копию без загрузки или исполнения upstream:

```bash
node scripts/vendor-drawio.mjs --check
```

Воспроизвести её из проверенного инертного извлечения:

```bash
node scripts/vendor-drawio.mjs \
  --source <drawio/src/main/webapp> \
  --manifest <package-manifest.json> \
  --viewer <official-viewer-static.min.js>
```

При повторной офлайн-сборке `--viewer` можно опустить: скрипт берёт сохранённые оригинальные байты из существующей копии и проверяет их закреплённый checksum. Для нового каталога viewer обязателен. Скрипт проверяет каждый исходный файл по manifest извлечения и не исполняет upstream-код.

```bash
node --test tests/*.test.mjs
npm run build
node scripts/vendor-drawio.mjs --check
```

В текущем проходе полный Node-набор дал 233 теста: 232 пройдены, один существующий fixture пропущен. Браузерные проверки и исходные исправления подтвердили явное подтверждение импорта и восстановление прежней схемы после save/close/reload; многостраничный HTML показал вторую страницу и счётчик `2 / 2` с постоянной панелью; Shift+Tab оставался в iframe/диалоге при `inert` фоне.
