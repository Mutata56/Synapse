## Colors

Near-black background, two quiet raised surfaces, violet active states and links, and a restrained mint tag accent. Existing CSS variables are the implementation source of truth. Text uses foreground roles; muted text is secondary context and must meet the contrast needed for its final rendered use.

### Tags extension

Tags secondary context uses the local `tags-muted` role for folders, dates, counts, descriptions and control labels. `tags-control` supplies the thin strokes around dark search fields, checks and grouped controls. Both values are scoped to the finder; the incumbent global muted token is preserved.

**The Semantic Accent Rule.** Within Tags, mint identifies tag membership and tag filters; violet identifies the selected note, active pane, match mode, links and focus. Keep those meanings distinct.

### All Notes extension

The local `library-muted` role mixes the existing text and background in the source color space. It carries excerpts, folders, dates, counts and secondary controls; it also supplies the inherited reading context color inside the library. The shared foreground, surface, violet and mint values remain unchanged.

**The Library Accent Rule.** Within All Notes, mint identifies tags; violet identifies focus, selection, the previewed card and the primary New note action.

### Files and Trash extension

The local `files-muted` role carries paths, dates, type labels, counts and quiet controls. `files-folder` is the default folder outline and `files-tag` is the bounded mint membership summary. `files-danger` is the implemented fallback for destructive controls when the shell has no danger alias. The dialog scrim darkens the existing work area without changing its palette. These roles remain local to Files, Trash and their dialogs; they do not replace the shell or Tags tokens.

**The Files Accent Rule.** Within Files and Trash, violet marks selection, keyboard focus, destinations and primary actions; mint identifies note tags, lavender identifies uncustomized folders, and the local danger role identifies destructive actions. Preserve user-assigned folder colors.

### Workspace shell

The shell uses existing semantic colors. Active document-tab labels use `foreground-strong`; their icons and thin inset underline use `link`. Selected search/bookmark labels and active tab-list entries retain `link`; contextual text and secondary controls use `foreground-secondary`. `foreground-muted` remains for quiet outline icons. The working region uses the neutral background; its empty page and active tabs use the existing overlay surface. No reference-screenshot palette is introduced.

**The Workspace Active Label Rule.** Document tabs use a strong foreground label with a link-colored icon and underline. Other active shell labels retain the link role, and context uses the secondary foreground. Keep selection and keyboard focus distinct.

### Calendar extension

The local calendar-muted role derives readable secondary context from the existing text/background tokens. Amber calendar-task identifies local plans; blue calendar-event identifies external events; lavender calendar-note identifies writing and journal marks; calendar-danger carries save/load failures and task removal. Task-specific colors remain a separate metadata dot in the day plan. These values are local to Calendar and preserve the global palette.

**The Calendar Source Rule.** Within Calendar, violet marks the selected date, today, completion, focus and primary actions; amber identifies local task previews, blue identifies external events and lavender identifies notes and journal marks. Preserve user task colors as task metadata, and pair source color with text or outline icons.

The source has local light overrides for these accents and native input color-scheme. Their compatibility capture uses synthetic semantic tokens; it is evidence of local compatibility, not an added global light theme.

## Typography

The existing Inter and system fallback stack supplies the interface. Section titles are compact and semibold; controls and note rows use a smaller workhorse scale. Monospace is reserved for source/code values.

### Shared font roles

The user pinned Obsidian's typography. Inter normal and italic variable faces
are copied unchanged from its packaged resources and loaded locally. They
replace BlockNote's static Latin-only font imports. Inter uses its normal
glyphs; the application no longer forces cv02/cv03/cv04/cv11/ss01/ss03. Both
faces contain the complete Russian and Latin alphabets. The bundled official
JetBrains Mono 2.304 variable faces supply code and source Markdown, following
the user's clarification and the Obsidian theme's source-font setting. Font
notices ship under `/fonts/`.

`src/typography.css` separates interface, text and monospace roles. Ordinary
interface text is 15px, compact labels retain 13/12px and existing dense
previews keep their local 13/14px scale. Primary note prose is 17px/1.5 at the
default editor zoom. H1–H6 use the Obsidian ratios 1.618/1.462/1.318/1.188/1.076/1
relative to that body. The inline note title uses the H1 ratio and the editor's
text zoom. Its height follows width, zoom and font loading instead of clipping
wrapped lines. Code uses 0.875em; raw Markdown keeps the readable 17px base.

### Tags hierarchy

The scoped title roles distinguish the view, the selected note and the results pane. Result titles are slightly emphasized; tree labels and search fields use the smaller row role. Context labels and mint tag summaries use the two smallest steps. Preview prose has the body size with a more generous reading line height and a maximum measure (72ch). Its Markdown subheadings follow the rendered document hierarchy (23px, 20px and 17px).

At the narrow container breakpoint, the view title becomes (22px), the reading title becomes (24px), and header inventory/result counts use the context step. Filter/match labels and the quiet Open action use the compact control step at both sizes. These are responsive adaptations of Tags, not a replacement global headline scale.

**The Dense Context Rule.** Small type carries metadata and compact tag summaries; note titles, search and primary actions remain visually stronger. Preserve the observed small interface steps instead of enlarging every row or flattening the hierarchy.

### All Notes hierarchy

The `library-` title roles distinguish the view, shelf, card and reading title. Excerpts use their own compact prose role; controls and dates stay subordinate. Cards without covers show a two-line title and up to four excerpt lines. Compact cards use the smaller title step (15px) and up to three excerpt lines; cards with covers use that smaller title step and two excerpt lines. Folders and footer tag summaries use the small context step (10px).

At library container widths of (680px) and below the view title becomes (23px) and the normal uncovered card title becomes (16px); at (450px) and below the view title becomes (22px). The reading prose inherits the Tags reader line height and measure (72ch), with the library's smaller body role. These observations belong to All Notes and do not revise the global or Tags type ramp.

### Files and Trash hierarchy

The `files-` title roles distinguish the view from the properties heading. The main title condenses at the three Files container thresholds; the narrow title keeps its own line height. Single-line names use the row role, search and named actions use the control role, and type/date context uses the metadata role. Table headings and mint membership summaries use the smaller column/tag steps. Dates use tabular figures. The empty-state heading remains a secondary title rather than a competing page heading.

The properties heading becomes (18px) on narrow layouts, while row names become (13px). Quick-look prose uses the local reader role and a bounded measure (72ch); its Markdown headings step through (20px), (18px) and the local reader-heading role. These are Files adaptations of the incumbent Inter family, not a new global type ramp.

### Workspace hierarchy

The shell uses normal Inter. Tabs, vault name, tree labels and empty-page
actions share the 15px interface role; ordinary labels are regular (400) with
line height 1.5. Result titles, context, keycaps and the narrow tab adaptation
retain compact roles. The generic button font reset was removed in the earlier
workspace pass, so these explicit role sizes now determine the rendered type.

## Do's and Don'ts

- Do use the semantic CSS variables and the existing icon family.
- Do preserve the application shell while improving a local view.
- Do theme focus, selection, scrolling and selected filters with established tokens.
- Do keep the Tags extension scoped and use its readable context color for dense secondary labels.
- Do preserve fixed row bounds, real tag-path hierarchy and explicit read-only preview actions in Tags.
- Do keep selected-tag summaries bounded and expose the full removable selection through +N.
- Do move focus into the visible pane after a narrow-layout pane switch.
- Do keep All Notes type, context and corner roles scoped to the library.
- Do use actual note excerpts when covers are absent, and keep editor and quick-reading actions explicit.
- Do preserve measured-width windowing, visible focus and the return context in All Notes.
- Do keep Files type, context, folder and corner roles scoped to the shared Files/Trash browser.
- Do keep the current folder route and selection actions reachable in narrow Files layouts.
- Do preserve fixed row bounds, folders-first ordering and mounted keyboard targets in Files and Trash.
- Do load Files quick look only on request and describe Trash dates as modification dates.
- Do keep workspace geometry and shape roles scoped to the shell while retaining each local view's container behavior.
- Do use the existing link and secondary foreground roles for workspace text states.
- Do keep shell controls reachable when panels collapse and preserve save-before-navigation behavior.
- Do keep Calendar source, context, type and corner roles scoped to the calendar workspace.
- Do preserve the displayed date anchor, bounded previews, complete paged day lists and focus restoration when changing visible Calendar regions.
- Do pair Calendar source color with labels or icons and keep task editing, journal opening and external sending explicit.
- Don't let a local feature silently change the global palette or typography.
- Don't impose decorative image covers or motion on dense note indexes.
- Don't turn preview tag actions into note edits or load image covers while filtering Tags.
- Don't invent file sizes or deletion timestamps in Files and Trash.
- Don't treat Calendar's synthetic light-token capture as a shipped global application light theme.
